# Documentation

## Structure

- Topics live as `docs/<topic>/en.md` + `docs/<topic>/ru.md` (architecture,
  skills, error-codes, ...). ADR: `docs/adr/NNNN-<slug>/{en,ru}.md`.
- `README.md` is always English and short: what it is, requirements, quick
  start, links to `docs/`, license. Details belong to `docs/`.
- `docs/openapi.json` is language-agnostic and generated by `task openapi:dump`.

## Rules

- Any topic change updates both language versions in the same change, with
  matching heading structure.
- No duplication: link to `README`/code instead of copying text.
- `docs/error-codes/{en,ru}.md` is synchronized with the `apperror` registry and
  guarded by a golden test; changing a code requires updating both files.
- ADR on every notable decision: context, decision, consequences. Existing
  examples: json/v2, minimal error codes, realtime off by default, runtime
  OpenAPI.
- Update `docs/skills/{en,ru}.md` when a skill changes (or use `add-skill`).

## Workflow

1. Pick the topic directory (create if missing with both files).
2. Write content in both languages; keep code samples identical.
3. Update `README.md` only if requirements/quick start changed.
4. Run `preflight` (docs sync is part of the definition of done).
