# Коды ошибок

Публичный контракт для клиентов (фронта). Коды стабильны: переименование или
удаление — только с `BREAKING CHANGE`. Сначала переиспользуйте существующий
код, конкретика — в `message`.

## API-ошибки (4xx)

| Код | HTTP | Когда |
| --- | --- | --- |
| `VALIDATION_FAILED` | 422 | некорректный/строгий JSON или ошибка валидации DTO |
| `UNAUTHORIZED` | 401 | токен отсутствует или невалиден |
| `TOKEN_EXPIRED` | 401 | токен истёк (клиент должен обновить) |
| `FORBIDDEN` | 403 | авторизован, но нет доступа |
| `NOT_FOUND` | 404 | сущность не найдена |
| `CONFLICT` | 409 | конфликт состояния (дубликат, версия) |
| `RATE_LIMITED` | 429 | слишком много запросов |
| `PAYLOAD_TOO_LARGE` | 413 | тело запроса превышает лимит |

## Runtime-ошибки (5xx)

Клиент всегда получает generic-сообщение; детали остаются в логах
(`type`, `message`, `trace`, `error`).

| Код | HTTP | Когда |
| --- | --- | --- |
| `INTERNAL` | 500 | неизвестная ошибка |
| `DB_QUERY_FAILED` | 500 | запрос к БД упал |
| `DB_CONNECT_FAILED` | 500 | БД недоступна |
| `DB_MIGRATION_FAILED` | 500 | миграция на старте не применилась |
| `REDIS_FAILED` | 500 | Redis недоступен |
| `HTTP_CLIENT_FAILED` | 500 | внешний HTTP-вызов упал |
| `PANIC` | 500 | перехваченная паника |
| `CONFIG_INVALID` | 500 | некорректная конфигурация в рантайме |

## Формат ответа

Успешные ответы оборачивают payload в `result`:

```json
{
  "result": {
    "token": "jwt",
    "user_id": "42"
  }
}
```

Ошибки приходят в конверте `error`:

```json
{
  "error": {
    "type": "VALIDATION_FAILED",
    "message": "email is invalid"
  }
}
```
