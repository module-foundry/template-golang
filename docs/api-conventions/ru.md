# Конвенции API

Как устроены тела ответов, чтобы API оставалось очевидным и дешёвым в
использовании. Правила реализованы в `pkg/response` и защищены golden-тестами.

## Успех

Каждый успешный ответ оборачивает payload один раз в `result`:

```json
{"result": {"token": "jwt", "user_id": "42"}}
```

- `result` содержит ровно DTO эндпоинта; доступ O(1) (`body.result.field`).
- Без лишней вложенности: `result.data`, `result.item.data` запрещены.
- Коллекции — плоский массив под `result`; словареобразные данные остаются
  объектом (`{"x": 1}`), а не массивом пар ключ/значение, который надо
  сворачивать.
- Ответы 204 без тела; не отправляем `{"result": null}`.
- HTTP-статус сохраняет смысл: 200/201/204.

## Пагинация

Метаданные страницы живут в `result.pagination`, а не в корне конверта:

```json
{
  "result": {
    "items": [{"id": "1"}],
    "pagination": {"page": 2, "per_page": 20, "total": 57}
  }
}
```

- `page`, `per_page`, `total` — каноничные поля (`pkg/response.Pagination`).
- `total_pages` выводится из `total` / `per_page`; дважды не отправляется.
- Один эндпоинт возвращает одну коллекцию; клиент листает страницы через
  query-параметры, а не итерациями и не отдельными запросами на элемент.

## Ошибки

Ошибки никогда не попадают в `result`; они используют конверт `error` со
стабильным `type`. См. `docs/error-codes/`.

## Антипаттерны

- Матрёшки конвертов: `result -> data -> payload`.
- Массивы из одного объекта «для единообразия» (заставляют делать `[0]` или
  поиск).
- Формы ответа, где клиент итерируется, чтобы собрать одну сущность (O(n) там,
  где хватает O(1)).
- Объекты-обёртки `{value, label, meta}` вокруг скаляра без причины.
- Разная форма у разных эндпоинтов (`result` тут, голый объект там).
- Одни и те же данные и в корне, и внутри `result`.

## Правила

- Конверт формируется только в `pkg/response`; хендлеры и сервисы не собирают
  его руками.
- Схема OpenAPI обязана совпадать с рантайм-телом (`result` — required); это
  держит golden-спека.
- Payload расширяется добавлением полей; переименование и удаление запрещены.
